🤖 AI客服机器人 · 设计方案
项目概览

本项目面向企业在线客服场景，设计并实现一个融合大语言模型（LLM）、检索增强生成（RAG）和智能体（Agent）技术的客户服务机器人系统。实现从"你问我答"到"能理解、能检索、能办事"的智能客服能力跃升。

功能需求

👥 用户管理

  • 用户注册与登录，JWT令牌鉴权
  • 角色区分：普通用户 / 管理员
  • 普通用户：发起对话、查看历史会话
  • 管理员：知识库文档管理 + 系统配置

💬 会话管理

  • 创建新对话会话，独立上下文
  • 会话列表展示、切换、删除
  • 消息持久化，刷新后继续对话

🧠 智能对话（核心）

  • 闲聊类 → 对话链直接回复
  • 知识类 → RAG检索后生成回答
  • 操作类 → Agent调用工具处理
  • 流式输出，逐字生成
功能需求（续）

📚 知识库管理

  • 文档上传（PDF / Word / TXT）
  • 自动解析 → 文本分块 → 向量化 → 入库
  • 文档列表、处理状态、删除
  • 检索测试：验证索引质量

📋 对话记录查看

  • 历史对话内容、时间戳
  • RAG回答标注引用来源

⚡ 非功能需求

关键技术方案

1. 流式输出方案

用户发送消息
→
FastAPI StreamingResponse
→
async生成器逐块推送
→
SSE (text/event-stream)
→
前端EventSource接收
→
实时追加到消息气泡

FastAPI使用StreamingResponse配合async生成器，将LangChain的流式迭代器逐块推送给前端。前端通过EventSource API建立SSE连接，每收到一个文本片段就追加渲染，直到收到结束标记关闭连接。

3. 知识库更新策略

文档上传后触发异步处理：解析→分块→向量化→入库。Chroma支持增量添加，新文档向量直接追加到已有集合，无需重建索引。文档删除时通过元数据过滤移除对应向量。文档处理完成后立即更新集合，用户下次提问即可检索到新内容。

4. 对话历史管理

采用滑动窗口策略，保留最近10轮对话。历史消息存储在MySQL中，每次对话开始时从数据库加载注入LangChain的ConversationBufferWindowMemory。窗口外的历史不注入当前上下文（避免Token超限），但用户可随时查看完整对话记录。

5. Agent意图识别与工具决策

Agent通过提示模板中明确描述各工具的适用场景来引导LLM决策。当意图不明确时触发追问澄清，连续两次无法判断后建议转人工客服，避免无效循环。
